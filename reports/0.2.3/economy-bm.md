# 0.2.3 경제·재화·BM 판단

## 현재 구현과 이번 변경

이번 상점 변경은 별도 0.2.2 피드백 브랜치의 검증·통합이다. `shop.ts`의 상품 정의·원장·보유·적용·중복 방지·저장 검증을 재작성하지 않았다. 일반 화면은 **준비 중**, 시험은 개발자 모드에만 있다. 실제 결제 API·서버 주문·영수증·계정 보유권이 없으므로 판매·결제 완료 기능으로 부르지 않는다. 새로운 직접 효용 상품을 UI 카탈로그에만 추가하지 않았다.

| 자원 | 현재 획득 경로 | 현재 소비처 | 이번 판단 |
|---|---|---|---|
| 구단 운영자금 | 입장 배분·스폰서·리그 배분·시설 매출·구단주 지원 등 실제 장부 | 선수 급여·영입/계약·시설 건설/유지·스태프·캠프 | 핵심 자원 유지. 입장 운영의 수입·인기 교환을 연결. 현금 과잉은 미해결 |
| 훈련포인트 | 기존 훈련 엔진의 지급 규칙 | 기존 팀/개인 훈련 규칙에 따른 소모 | 기존 획득·성장 한도와 체력·피로 비용을 유지. 유료 판매 없음 |
| 기록포인트 | 기존 시험 지급의 잔액만 보존 | 개발자 모드에서 기존 테마 시험만 가능 | 정상 지급·구매 중단. 새 유료재화로 환산하거나 지우지 않음 |

## 상품 후보와 선행 조건 — 판매 중인 상품이 아님

**반복 효용 후보:** 연간 예산 안에서 선택하는 캠프·개인 육성·회복 프로그램. 먼저 구단 자금으로 수행하는 무료 플레이의 의사결정을 완성한다. 그 후 유료 시간 절약이나 자원 보완이 있더라도 POT·월별 훈련 기회·체력/피로·연간 사용 한도와 기존 드래프트 공급을 우회하지 않는지를 비교해야 한다. 프로그램 효과·가격·구매 횟수는 아직 확정하지 않았다. 현금이 남는 후반에 자금을 더 파는 것은 상품 가치의 근거가 되지 않는다.

**영구·시즌 콘텐츠 후보:** 추가 시나리오, 구단 로고·인물 이미지·경기 시각 팩. 실제 에셋, 적용 위치, 무료 기본 선택과의 차이, 계정/회차별 보유 범위가 있어야 상품으로 인정한다. 색상 테마 3종만으로 주력 BM의 효용을 입증했다고 보지 않는다. 플레이에 필요한 기본 기록·저장·라인업 기능을 유료 전용으로 막지 않는다.

**편의 후보:** 여러 운영 계획의 보관·비교, 추가 시나리오 편집 도구. 기존 무료 저장 슬롯·내보내기·기본 분석은 제거하지 않는다. 유료 편의가 클릭 수만 늘렸다 줄이는 인위적 불편 해소가 되지 않도록 실제 반복 사용을 검증한다. 이번에는 편의 상품을 구현하거나 판매하지 않았다.

**보류:** 직접 능력치 구매·확률형 선수 공급·훈련 스킬. 현재 공급/성장·중복·계약·로스터에 영향이 커 이번에 넣지 않는다. 확률형을 영구 금지하는 선언이 아니라, 실제 공급량·무료 접근·중복 처리·이력·상한과 별도 서비스 검토가 완료되기 전 판매하지 않는 경계다.

## 무료·유료 경험과 경제 검증

현재 정상 플레이는 비구매 상태로 시즌·PS·계약·FA·드래프트·다년 전이를 진행한다. 과금하지 않아 적자나 육성 정체를 강제로 만드는 변경은 없다. 현재 유료 경험은 존재하지 않으며 가상의 매출·전환율·객단가를 수치로 제시하지 않는다.

추후 무료로 획득한 프리미엄 재화와 구매분이 동일 상품에 접근하게 하는 안을 우선 검토한다. 구분이 필요하면 다른 열등 화폐를 추가하기보다 원장 출처로 구분한다. 무료 수급·반복 소비·시즌 한도·환불 시 회수 범위·기존 보유권을 함께 정해야 한다. 가격이나 환율을 지금 하드코딩하지 않는다.

검증은 ① 구매하지 않는 표준 진행 ② 무료 획득을 적극 활용한 진행 ③ 상한까지 구매한 진행의 시즌 성장·영입 공급·재정·승률·플레이 시간 차이를 같은 시드/상황에서 비교하는 방식이 적절하다. 기존 결과를 돈으로 다시 추첨하거나 경기 난수를 구매에 따라 바꾸지 않는다. 이번 실제 검증은 상점 경계·보유권 보존과 입장 정책 비교이지 위 유료 경제 검증의 완료가 아니다.

## 광고·결제·구매 복원 경계

선택형 광고는 필수 진행에서 분리하는 후보지만 SDK/서버 완료 확인은 미연결이다. 개발자 시험 버튼을 시청 완료로 간주하지 않는다. 도입하려면 일/시즌 한도와 중복 지급 방지, 실패/취소, 저장 복원, 기존 자원 상한을 검증해야 한다.

실결제는 인증된 서버 주문 → 결제 제공자 영수증 검증 → 유일 거래 ID에 따른 지급 → 계정 보유권/복원 → 환불·취소 처리라는 별도 경계가 필요하다. 숨겨진 개발자 토글과 로컬 세이브는 서버 인증이나 유료 소유권 증명이 아니다. 개발자 결제 경계 시험은 미연결 오류를 반환하고 실제 돈이나 유료 권리를 만들지 않는다. 외부 가입·계약·청구를 수행하지 않았다.

## 다음 결정

시설 완성 후에도 가치 있는 **비과금 반복 투자** 하나의 비용·실효과·대체 선택을 먼저 검증한다. 그 결과가 유료 프로그램의 효용/상한 설계에도 필요하다. 10년 이후 현금 한도는 회차 간 자산 계승 문제로 분리하고, 현금·선수·시설·기존 보유권의 미리보기가 없는 상태에서 임의 삭감하지 않는다. [0.2.2 별도 보류 보고서](version-reports/0.2.2/deferred.md)는 후속 후보의 원문으로 보존한다.
